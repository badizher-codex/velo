# FIELD GATE — hosts observed in the maintainer's real browsing that Sentinel
# must never BLOCK. This is the hard gate as of model-v3; the synthetic benign
# FPR is now reported but no longer blocks a release.
#
# Why the change: the FPR is measured on the test split that prepare_data.py
# itself produces, and that split keeps getting harder as the generator gets
# more realistic — so the number is not comparable between models. model-v1
# passed it at 0.74% and then blocked YouTube's video servers in the field;
# model-v3 fails it at 1.0074% while blocking 3 hosts out of 93. The gate was
# not failing for the first time, it had been failing in the comfortable
# direction. A gate has to be measured on a set that does NOT move with the
# thing under test.
#
# Provenance: every line below was logged by Sentinel in shadow mode during
# ordinary browsing (Sentinel SHADOW ... in %LOCALAPPDATA%\VELO\logs). They are
# the hosts a real session actually produced, not a list anyone sat down and
# imagined — which is exactly why they caught what the imagined lists missed.
#
# Deliberately NOT here, and why:
#   * OneTrust / TrustArc / cookielaw   — consent platforms, blocking is defensible
#   * connect.facebook.net, 33across    — tracking pixel / adtech
#   * New Relic, Dynatrace, Hotjar      — RUM + session recording
#   * links. / improving.duckduckgo.com — click tracking + telemetry
#   * *.cloudfront.net                  — SentinelClassifier.IsOpaqueSharedHost
#                                         never asks the model about these, so
#                                         gating on them would measure nothing
#
# Adding a host here is a promise that blocking it breaks something a user can
# see. Keep it that way.
